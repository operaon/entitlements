# Processo de release — entitlements

As versões devem ser criadas a partir de tags semânticas após CI, revisão e validação de compatibilidade. Nenhum release fictício é criado automaticamente sem uma versão de produto aprovada.

## Procedimento

1. Atualizar CHANGELOG.md.
2. Confirmar testes e contratos.
3. Criar tag semântica, por exemplo v1.0.0.
4. Publicar a release no GitHub com notas técnicas e migração.
5. Registrar rollback e impacto operacional.
